# Klein Explorer · What should a GitHub showcase prove?

**Question.** Should a public agent-skills repo put more media in its README?

The first search looked at design and media projects. [Remotion](https://github.com/remotion-dev/remotion) opens with a product image and directs readers to a quick start. [Impeccable](https://github.com/pbakaus/impeccable) shows two results from the same brief and model. These READMEs demonstrate how media can explain a product or make a claimed difference inspectable.

**Challenge.** The sample favored products with visual outputs. A second pass looked at workflow and engineering repositories. [Superpowers](https://github.com/obra/superpowers) emphasizes its method and installation per agent. [llm.c](https://github.com/karpathy/llm.c) offers a reproduction path and example training output. Those cases show two ways documentation can earn attention with runnable evidence.

**Decision.** Keep an actual render as the [Batcave README](../../../README.md) hero. Give visual skills a comparison or final artifact. Give research and collaboration skills a short example with its sources or PR evidence.

**Limit.** This was a purposive sample of public READMEs reviewed on 23 November 2026. It shows presentation choices. The effect on adoption, stars, and installs is unknown. To test the recommendation, ask new readers to find a relevant skill and explain how they would try it, using the old and new READMEs as separate conditions.
