# Storage, privacy and publication

Default local/private; verify actual remote visibility and permissions separately from manifest. Never create public repos or publish journals, personal details, client data, unreleased story assets, credentials or licensed inputs merely because requested a repo. Confirm authorization, scope and intended audience before publication. Private Git is not a secure vault: clones, forks, caches, logs, backups and commit history may preserve content even after deletion. Use encrypted local or access-controlled external storage for sensitive data; minimize collection and retention. Don't store access tokens, API keys, private keys, passwords, signed URLs with secrets or environment secrets. Use secret manager, .env.example with fake values, ignore rules and actual secret scanning. If a secret exposed, rotate/revoke immediately and follow authorized cleanup; removing a file from HEAD alone is insufficient. History rewrite requires explicit authorization and coordination, not routine migration.

Keep versioned text small and useful. Large media/datasets may use R2, S3-compatible storage, Drive, Git LFS or local archive depending on access, quota, licensing and retention. Git LFS is not a backup. Avoid unstable signed links as canonical IDs. Store stable object key/version or URI plus retrieval mechanism, optional checksum (actual only), size/mime, rights/consent classification, producer/source, status, dependencies, review date and backup policy. Verify access and integrity when needed. If link unavailable, label missing; never invent asset. External assets need backups and restore checks proportional to consequence. Keep public-safe index distinct from private inventory. Keep canonical project state in one location, not duplicate full media across systems. Use git-native text files and relative links where possible so migration doesn't require proprietary services.

Before remote write: inspect staged diff and relevant history for sensitive data, confirm visibility/target, check ignore rules and asset rights, ensure approved scope, report any unresolved sensitive material. Sanitize test fixtures/evidence including screenshots, browser logs and URLs. Avoid exporting private user-trained context into public AGENTS.md. If deletion requested, discuss limits of clones and history, avoid unnecessary retention; never promise full erasure without evidence.
